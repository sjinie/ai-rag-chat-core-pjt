# 유사 사례는 개황 문장 유사도로 찾고, 숫자는 정형 DB에서 조회한다

텍스트 임베딩은 숫자의 크기를 비교하지 못해서("14.1℃"와 "14.3℃"가 가깝다는 것을 모름), 관측값을 그대로 임베딩해서는 "오늘과 날씨가 비슷한 날"을 찾을 수 없다. 그래서 같은 관할 지방청이 낸 개황 가운데 **오늘 문단이 오늘 개황과 비슷했던 과거 날짜**를 임베딩 유사도로 찾고, 그날 선택한 지점의 관측은 임베딩하지 않은 SQLite에서 날짜·지점으로 정확히 조회한다. 사람이 쓴 예보 문장끼리는 같은 문체와 어휘를 써서 임베딩이 잘 맞고, 숫자는 계산·비교를 코드가 맡는다.

## Considered Options

- **관측값을 문장으로 바꾸지 않고 임베딩**: 숫자 비교가 되지 않아 탈락.
- **5년치 일별 관측을 LLM으로 문장화한 뒤 임베딩**: 97개 지점 × 1,826일 ≈ 17.7만 건. 출력 토큰만으로 약 9.6만 크레딧이 들어 보유 크레딧(약 7만)을 넘어 탈락.
- **개황 원문만 근거로 사용**: 개황은 예보라서 실제 결과가 아니고, 권역 단위라 지점 비교가 안 되며, 6개 기후 항목이 거의 없어 탈락.
- **다른 관할 지방청의 비슷한 개황까지 사용**: 다른 지역의 결과는 선택한 지점의 답이 되지 못하고, 지역명 때문에 유사도도 낮아 같은 지방청으로 제한.

## Consequences

- 날짜 조건을 두지 않으므로 다른 계절의 날이 뽑힐 수 있다. 그래서 유사 사례의 관측은 그날 기준값과의 차이와 함께 보여 준다.
- 문장 유사도는 시간대 차이("저녁부터 비"와 "아침까지 비")를 잘 구분하지 못한다. 상위 후보를 프롬프트2가 질문에 맞게 다시 고른다.
- 이 방법이 기준값보다 실제 결과에 가까운지는 사후 검증으로 확인해야 한다.
